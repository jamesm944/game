# Wayfinder #162 — current navigation audit

## Verdict

ADR-0003 phase 1 is substantially implemented, with later formations and naval support layered on. Phase 2 flow fields are absent. **There is no existing evidence that either phase-2 trigger has fired**: current performance runs measure whole-tick cost with synchronous pathfinding, not concurrent real-worker turnaround or isolated path-application cost. Ticket #162 still needs a controlled cross-donor benchmark.

The correctness base is reusable, but a fair benchmark must preserve Age of Wind's command timing, group/slot behavior, medium- and owner-specific passability, mutation invalidation, steering, and replay contract. A point-to-point path library comparison alone would miss most of the current system.

Two smaller ADR mismatches matter to traces:

- New group orders do not explicitly stall members during the two-tick leader search. Existing queues are replaced only when the response applies, so an already-moving unit can continue its old activity during that window. `src/sim/systems/movement.ts:563-567,615-616,671-681`. The explicit hold exists for **individual repaths**. `src/sim/systems/movement.ts:865-867,1352-1357`.

## Semantics a cross-donor benchmark must preserve

1. **Tick and command semantics:** 30 Hz fixed steps; commands drain only at target ticks; leader results apply at `issueTick + 2` or later in request-ID order; a late due response holds the tick rather than allowing arrival timing to alter the simulation. Compare worker wall-clock latency separately from simulated completion ticks.
2. **Grid legality and cost:** binary passability, eight neighbors, no diagonal corner cutting, `1000/1414` raw-path costs, deterministic nearest-passable goal substitution, and no-route behavior. Validate pulled segments independently. Do not compare a navmesh's continuous distance directly with the integer raw-grid cost without an explicit normalization.
3. **Group semantics:** ascending IDs, centroid leader selection and low-eid ties, one leader request per order, deterministic slot dealing, direct-LOS follower shortcut, final exact slot destination, queued-destination starts, and individual recovery repaths.
4. **Planner/steering boundary:** buildings and terrain are planner obstacles; units are handled by boid/push-apart/FSM. Measure path quality separately from stuck count, crowd density, and completion time. A donor crowd solver must run against equivalent radii, speeds, activities, and parked bodies.
5. **Passability views:** land, naval, and owner-specific gate planes are different requests. Preserve immediate site blocking, destruction freeing, versioned invalidation, live segment revalidation, and stale-result behavior. Separate current grid-update/version/snapshot/repath costs from a donor's navmesh rebuild cost; there is no current mesh rebuild to compare directly.
6. **No elevation navigation effect:** adding cliff constraints or elevation costs would be a rules change, not donor parity.
7. **Determinism:** fixed entity iteration and tie order, seeded PRNG only, exact f64 component digests, and repeated-run equality. `src/sim/core/digest.ts:1-12,55-99`; `src/sim/core/prng.ts:1-18,56-85`; `src/sim/core/trig.ts:1-11,96-113`. Require each donor to be deterministic across repeated runs and async delivery patterns; do **not** require different donors to choose identical equal-cost paths unless their tie-breaking and geometry are deliberately unified.
8. **Metric definitions:** define completion as activity completion, not merely entering the loose arrival region. Separate unreachable no-op, awaiting path, stalled, propagated-Parked, and genuinely permanently stuck. Record issue-to-response wall time, issue-to-apply ticks, `blockedTicks`, path-application main-thread time, repath count, and mutation-to-repath cost.

## Benchmark blind spots and determinism risks

- **The existing load numbers cannot trigger phase 2.** The 300-Pop harness uses synchronous transport, issues `gather` rather than concurrent leader searches, and warms up for 120 ticks before measurement. `tests/helpers/budget-scenario.ts:8-14,105-112,190-210`. Recorded p95 values are whole-sim costs, not the two ADR metrics (`docs/m5-budget.md:13-29`). The scheduler “budget” test pumps 5,000 prebuilt fake responses on a 4×4 grid with a 200 ms ceiling, so it does not test real waypoint application or the ~2 ms trigger. `tests/path/scheduler.test.ts:318-346`.
- **Async tests are functional, not load tests.** The mock computes synchronously and injects ID-scripted delivery delays; no test spawns the real browser Worker. `tests/helpers/mock-path-worker.ts:30-67`; `src/game/paths.ts:1-5`. The golden trace has only 12 Pops/two group orders and permits final slot error up to 1.5 tiles. `tests/golden/m1t4/case.json:70-101`; `tests/golden/m1t4/golden.test.ts:308-318`. It cannot characterize crowd load, latency under queueing, or throughput.
- **Small-scenario coverage hides scale failures.** Movement tests use 16×16 maps and at most two units; the golden uses 32×32/12 units. There is no dense large-group, many-simultaneous-destination, mixed-radius, mixed-medium, naval-mutation, or elevation-navigation stress case. Existing formation speed tests inspect stored caps, not sustained formation geometry (`tests/formations.test.ts:253-292`).
- **LOS is not a true general supercover.** The walk always takes a diagonal while both axes remain, checking that diagonal's two orthogonal neighbors. `src/sim/path/astar.ts:182-216`. On shallow slopes it can skip a tile intersected by the actual center-to-center segment; it can also reject clear segments through extra conservative checks. Tests assert open shallow-slope visibility and diagonal pinches, not blocked shallow-slope crossing geometry (`tests/path/astar.test.ts:232-251`). Use an independent traversal oracle and decide whether parity means preserving or first fixing this behavior.
- **Cache purity relies on version discipline.** The LRU key omits grid bytes and medium/owner identity. `src/sim/path/engine.ts:66-87`. This is safe only while every semantic plane mutation bumps the shared version and request versions uniquely identify their snapshot. A benchmark that mutates arrays without bumping versions can serve stale paths and falsely appear deterministic.
- **A blocked pump can already have applied earlier responses.** `pump` applies each available response in order, then returns `false` upon a later missing due response. `src/sim/path/scheduler.ts:209-230`; this ordering is explicitly pinned by `tests/path/scheduler.test.ts:231-249,373-392`. Thus `world.step` has not advanced, but earlier callbacks may already have mutated component rows despite the broader “world state stays” comment in `src/sim/core/world.ts:252-267`. The sequence is deterministic and IDs prevent reapplication, but benchmark instrumentation must sample only committed ticks and must not assume a blocked call is side-effect-free.
- **Dynamic mutation can drop an in-flight group order.** Stale group results are discarded without `onDiscard`/reissue, while individual repaths explicitly release and retry. `src/sim/path/scheduler.ts:222-230`; `src/sim/systems/movement.ts:599-686,888-956`. Existing placement/destruction tests mutate **after** the leader route applies, so they do not cover this gap. Record stale-group cancellation separately from pathfinder failure or stuck count.
- **Snapshot traffic can dominate donor comparisons.** Every request copies the full plane before posting (`src/sim/path/scheduler.ts:155-192`), and naval/per-owner views may also be rebuilt. Comparing only search-engine nanoseconds would exclude a real current cost and favor an integration with different snapshot ownership.

## Phase-2 decision

**No, ADR-0003's phase-2 trigger does not already have evidence.** Nothing in the current tests or budget reports measures concurrent leader-search real-worker turnaround against one 30 Hz tick, or real path-application cost against ~2 ms/tick. Existing whole-tick results are useful regression context but cannot answer that question. Keep flow fields uncommitted until #162 records those metrics alongside completion, crowd, mutation, and replay outcomes on identical traces.
